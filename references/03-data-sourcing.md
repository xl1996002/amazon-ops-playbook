# 取数口径与数据来源

> 页面文案和广告方案的每个事实都必须有出处。这一节定义「从哪拿、拿什么、怎么判断能不能用」。

## 1. 三种数据来源，优先级从高到低

| 优先级 | 来源 | 可信度 | 用法 |
|---|---|---|---|
| 1 | 用户后台导出 / 商品真实资料（尺寸表、检测报告、包装清单） | 最高 | 参数类事实的**唯一**依据 |
| 2 | 商品详情页抓取（第三方数据工具 / 页面实测） | 高 | 竞品结构、价格、评论、类目排名、关键词 |
| 3 | 用户口述、经验判断 | 低 | 只能作为待验证假设，必须标注 |

**参数（尺寸/材质/承重/认证/防水）只能来自第 1 类。** 从竞品页面看到「防水」不代表自家的产品防水。

## 2. 取数流程

先确认数据源可用。工具调用前先查参数，不要凭记忆拼参数。

### 2.1 单品完整数据（自有链接或竞品参考）

按用途挑工具，不要一次拉全部：

| 要拿的信息 | 用哪个能力 |
|---|---|
| 标题、五点、价格、评分、评论数、类目排名、变体 | 产品详情类 |
| 结构化页面诊断（模块完整度、卖点分布） | 产品报告类 |
| 标题/五点/描述的原始文本 | 产品内容类 |
| 评论与买家原话 | 评论类 / 买家之声类 |
| 流量词与关键词反查 | 产品流量词类 |
| 竞品关键词交集 | 竞品关键词类 |
| 同类产品差异点 | 相似产品特征类 |

### 2.2 市场与类目

| 要拿的信息 | 用哪个能力 |
|---|---|
| 类目规模、集中度、价格带 | 类目报告类 |
| 类目下热销产品 | 类目产品类 |
| 关键词搜索量与趋势 | 关键词详情 / 关键词趋势类 |
| 关键词搜索结果页竞争度 | 关键词搜索结果类 |

### 2.3 抓完必须做的三件事

1. **落一份数据快照**（表格或 Markdown），字段列全，标明抓取日期与站点。价格与排名是时效数据，必须带日期。
2. **交叉校验**：抓到的标题与页面实际标题对不上、评论数与页面显示差异过大时，以页面实测为准，并在交付物里写差异。
3. **区分事实与推断**。抓取到的写「实测」，推理出来的写「推断」，两类不能混在同一张表里不加标识。

## 3. 没有数据源时怎么办

按以下顺序降级，降级了什么必须告诉用户：

1. 请用户提供后台导出（业务报告 / 搜索词报告 / 商品资料表）
2. 请用户提供页面截图（主图、五点、A+、价格与评论区）
3. 只基于用户给的产品资料写，**不做市场判断、不给竞品结论**
4. 明确在交付物开头写：「本次未取得市场实测数据，以下竞品/市场结论均为待验证假设」

**绝不允许**：编造搜索量、编造竞品价格、编造类目排名、编造评论数。

## 4. 数据质量判断（拿到导出先看这三条）

- **口径**：时间范围、站点、币种、是否含税、是否含广告花费 —— 四项没确认，数字不能直接比
- **完整性**：行数是否等于应有 SKU 数，是否有整列为空
- **一致性**：同一指标在两份报告里是否对得上（对不上时先查口径，不要挑好看的那个用）

## 5. 从数据到结论

每条结论都要写成「证据 → 判断 → 动作」三段式，缺一段就不算结论：

```
证据：目标词 A 曝光 12,000 / 点击 180 / CTR 1.5%，类目均值 0.4%
判断：CTR 高于均值，主图与标题吸引力没问题；转化率 3.2% 低于均值 8% → 卡在详情页
动作：优先级放在五点与 A+，而不是加广告预算
```

只写「转化偏低，建议优化 Listing」属于废话，返工。
